# Connect Kiro to AWS for this portfolio

This is a local development setup. It does **not** add AWS credentials or AWS API access to the public website.

## Why it matters

The AWS Student Builder Challenge guide describes connecting a coding agent to an AWS project using the Agent Toolkit for AWS. The toolkit provides the agent with current AWS documentation, AWS MCP tools, and task-specific skills/rules. The agent operates using the permissions of the AWS identity you sign in with.

## Setup (Windows + Kiro)

1. Keep this folder (`adarsh-portfolio`) on your laptop and open the **folder itself** in Kiro.
2. In your browser, sign in to the AWS Console and check the account and Region shown for your project. Use the account you intend to use for the challenge.
3. On AWS Console Home, choose **Copy agent prompt**. AWS generates a setup prompt for your project and selected Region. Use that generated prompt rather than a random setup command from the internet.
4. Paste the entire setup prompt into Kiro's chat, **not** into the regular PowerShell terminal. Read each proposed command and approve it only when you understand what it does.
5. The setup may ask for a profile name, install missing CLI components, and run `aws login` to open browser sign-in. Choose a simple profile name such as `adarsh-portfolio` when prompted. Do not create or paste long-lived access keys.
6. When setup completes, start a **new Kiro conversation** with this same folder open so the new AWS MCP connection and skills are loaded.

## Verify without changing AWS resources

Paste this into the new Kiro conversation:

> Check that the AWS MCP Server is connected and I am signed in to AWS. Confirm the active profile and Region for this project. Do not create, modify, or delete any AWS resources. Inspect this portfolio's files and tell me the safest next steps to deploy this static site using AWS Amplify Hosting. Do not edit files yet.

Check that Kiro explicitly reports the connection and the correct Region. If the MCP connection or sign-in check fails, resolve that before asking it to deploy anything.

## Use the agent as part of the build

After the read-only verification works, try this scoped task:

> Review the portfolio locally for accessibility, responsive layout, broken internal links, and JavaScript errors. First report your findings and the files you would change. Do not touch AWS resources. Wait for my approval before editing files.

Then review the agent's findings, apply changes deliberately, and test the site locally. For deployment, ask it to explain the Amplify plan and any costs before approving resource-creating actions.

Capture only after the steps actually succeed:

- A screenshot of the agent checking current AWS documentation or reviewing the Amplify plan.

## Safety and accuracy

- Never commit `.env` files, access keys, session tokens, or credentials to GitHub.
- The website terminal is a local scripted interaction. It does not execute shell commands or call the AWS account.
- Do not say “AWS coding agent connected” in public documentation until the verification prompt succeeds.
- The setup flow and AWS Console labels can change. Use the prompt and current instructions generated by your own AWS Console.
